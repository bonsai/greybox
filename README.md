# GREYBOX

**Human × AI — 任せる、検証する、決断する。**

GREYBOX is a junior-engineer learning game about choosing the right boundary between AI delegation and human understanding, verification, and decision-making.

## Portable story source

- `story/stage01.json` — engine-independent story and choices
- `story/schema.json` — JSON Schema for the story format

The JSON story is the canonical source. Ren'Py is a runtime adapter, not the
place where story content is hard-coded. `game/story/` is generated; run
`python tools/sync_story.py` after editing anything in `story/`.

## Story format v1

Scene types:

- `dialogue`: `speaker`, `text`, and `next`
- `choice`: `text` and `choices`; each choice can declare `effects` (state
  deltas) and a `next`
- `event`: a named event handled by the runtime adapter
- `ending`: terminal result with `title`, `text`, and `outcome`
  (`success` / `partial` / `failure`)

Top-level `events` maps an event name to **data-only effects**. Event scenes may
only reference a name declared there, and the adapter applies the effects. Story
data never contains executable code or expressions.

State is a flat dictionary seeded from `initial_state`. Numeric effects are
added to the current value; booleans and strings replace it. Every `effects` key
must exist in `initial_state`, so a typo fails validation instead of silently
creating a new variable.

The schema validates structure. `tools/validate_story.py` checks the semantics:
unique scene and choice IDs, valid speaker and event references, existing `next`
targets, no unreachable scenes, no cycles, and at least one reachable ending.

## Settings (YAML) and data (JSON)

Settings describe what the stage *is*; data is what the game *reads*.

| Kind | File | Holds |
| --- | --- | --- |
| Settings | `story/config/stage01.yaml` | story id, characters, learning goals, quiz policy, generation settings |
| Settings | `story/config/quiz.format.yaml` | question types, length limits, question rules, LLM prompt template |
| Data | `story/stage01.json` | scenes, choices, effects, endings |
| Data | `story/quiz.stage01.json` | questions, choices, answers, explanations |

API keys never appear in the YAML. The config names environment variables
(`LLM_BASE_URL`, `LLM_API_KEY`, `LLM_MODEL`) and the tools read them.

```powershell
bin\quizgen.cmd --check      # do settings, story and quiz agree?
bin\quizgen.cmd --dry-run    # print the prompt that would be sent
bin\quizgen.cmd              # generate the missing questions and append them
```

`quizgen` is the LLM patch: it finds scenes without a question, builds the
prompt from `quiz.format.yaml` plus the goals, asks an OpenAI-compatible model,
rejects anything that does not match the story (unknown scene, duplicate
question, answer outside its choices), and appends only what survives.

When questions run out and generation is not possible, `exhausted.fallback`
decides what happens — `recycle` prints a review set of the least-covered
questions without touching the data, `stop` exits 2 so a human decides.

## Running locally

Requires the [Ren'Py SDK](https://www.renpy.org/latest.html) (8.5.3 or newer).

```powershell
# Play
& "$env:RENPY_SDK\renpy.exe" C:\Users\you\greybox

# Compile only (catches .rpy syntax errors)
& "$env:RENPY_SDK\renpy.exe" C:\Users\you\greybox compile

# Lint (unused labels, undefined screens, style problems)
& "$env:RENPY_SDK\renpy.exe" C:\Users\you\greybox lint
```

`--warp game/script.rpy:<line>` jumps straight into the game, which is handy for
smoke-testing without clicking through the main menu.

## Tools

```bash
bin/check                             # everything below, in one go (Windows: bin\check.cmd)

python tools/sync_story.py            # story/ -> game/story/
python tools/sync_story.py --check    # fail if the copy is stale (CI)
python tools/validate_story.py --verbose
python tools/validate_quiz.py
python tools/quizgen.py --check       # settings <-> data consistency
python -m unittest discover -s tools -p "test_*.py"
```

## Building a distribution

```powershell
& "$env:RENPY_SDK\renpy.exe" "$env:RENPY_SDK\launcher" distribute `
    C:\Users\you\greybox --package pc --destination dist
```

The result is `dist/greybox-0.1.0-pc.zip`. CI runs the same command on every
push to `main` and uploads the zip as the `greybox-windows` artifact.

## Design principles

1. AI may do work; its completion claim is not proof of correctness.
2. Human verification should be proportional to risk.
3. The player is evaluated on quality, evidence, risk management, and
   efficiency—not on reading every line or blindly trusting the AI.
4. Story data must not execute embedded Python or arbitrary expressions.
5. Scene and choice IDs are stable identifiers; display text may change without
   breaking references.
